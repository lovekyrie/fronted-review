# Learning Journal: 2026-10-11

## Q1: docs:build 为什么报 `_template.md` Element is missing end tag？

**Context**: `interview/en/daily-prep/_template.md`

**Key points**:

- 报错 `(4:67)` 是生成后的 Vue SFC：第 4 行 `<template>` 里，第 67 列是标题中的 `<topic>`。
- `<topic>` 被当成未闭合的 HTML 标签。`` `<slug>` `` 在反引号里，已被转义。
- 中文标题 `<主题>` 不是合法标签名，所以中文模板能编过。

**Details**: [../knowledge/tooling/vitepress-raw-html.md](../knowledge/tooling/vitepress-raw-html.md)

## Q2: Docker 里 pnpm install 为什么报 ERR_PNPM_IGNORED_BUILDS？

**Context**: `Dockerfile`

**Key points**:

- `npm install -g pnpm` 装到的新版默认不跑依赖构建脚本，跳过 `esbuild` 的 `postinstall` 时直接失败。
- 镜像里不能交互执行 `pnpm approve-builds`，仓库也没有 `onlyBuiltDependencies`。
- 需要显式允许 `esbuild`。只关掉 strict 检查，二进制仍然不会装上。

**Details**: [../knowledge/tooling/pnpm-ignored-builds.md](../knowledge/tooling/pnpm-ignored-builds.md)

## Q3: 能否固定 pnpm 版本，从而不配 onlyBuiltDependencies？

**Context**: `Dockerfile`

**Key points**:

- 可以。锁到 `pnpm@9.15.9`：这一代默认执行依赖 `postinstall`。
- pnpm 10 即使不报 `ERR_PNPM_IGNORED_BUILDS`，也不会跑 `esbuild` 脚本，Alpine 上 `docs:build` 仍然缺二进制。
- 版本写在 `package.json` 的 `packageManager`，Dockerfile 用同一个版本号安装。

## Q4: 作用域笔记里写的 3 和 1，为什么页面上是 3 和 4？

**Context**: `interview/jscore/basic/scope-closure.md`

**Key points**:

- 第 15 行的 `1.` 和上面的 1、2、3 只隔了一个空行，仍是同一张有序列表的第 4 项。
- 有序列表只认第一项的数字，后面写的序号会被忽略。
- 空行拆不开列表。要重新从 1 开始，中间需要标题、段落、`---` 或注释。

**Details**: [../knowledge/tooling/markdown-ordered-list.md](../knowledge/tooling/markdown-ordered-list.md)

## Q5: fetchA / fetchB 前面不加 await，是不是也并行？

**Context**: `interview/jscore/basic/es6.md`

**Key points**:

- 不加 `await` 时，两次调用会立刻先后启动，请求在时间上重叠。
- 变量拿到的是 Promise，`async` 函数不会等它们结束，失败也可能没人处理。
- 并行还要结果：先调用再 `await`，或用 `Promise.all`。连续 `await` 才是串行。

**Details**: [../knowledge/javascript/async-await-parallel.md](../knowledge/javascript/async-await-parallel.md)

## Q6: 不需要结果就可以去掉 async，有依赖就必须 await？

**Context**: `docs/knowledge/javascript/async-await-parallel.md`

**Key points**:

- 函数体没有 `await` 时，`loadData` 不必是 `async`。连续调用 `fetchA()`、`fetchB()` 会让请求重叠。
- 并行来自调用之间没有等待，不是来自有没有 `async`。
- `fetchB` 要用 `fetchA` 的返回值时，必须等 `fetchA` 结束再调用 `fetchB`，这时外层要写成 `async`。

## Q7: 「Promise 优先于 setTimeout」是不是把 setTimeout 说成了微任务？

**Context**: `interview/jscore/basic/event-loop.md`

**Key points**:

- `优先于 setTimeout` 表示 `Promise`、`MutationObserver` 比 `setTimeout` 先执行。
- `setTimeout` 仍是宏任务。当前栈清空后先排空微任务，再跑下一个宏任务。

**Details**: [../knowledge/javascript/microtask-before-macrotask.md](../knowledge/javascript/microtask-before-macrotask.md)

## Q8: 手写 Promise 为什么要回调数组？执行 executor 就算 Promise 了吗？

**Context**: `interview/jscore/basic/async-program.md`

**Key points**:

- `then` 可能发生在 `resolve` 之前，回调先放进数组；一个 Promise 可以有多个 `then`。
- `executor(resolve, reject)` 只是立刻把改状态的函数交给用户，稍后由用户决定何时 `resolve` / `reject`。
- 像 Promise 靠的是状态机、`then` 登记、settled 后补发这三件一起。

**Details**: [../knowledge/javascript/promise-callback-queues.md](../knowledge/javascript/promise-callback-queues.md)

## Q9: 异步回调里抛错，为什么外层 catch 接不住？

**Context**: `interview/jscore/advanced/promise.md`

**Key points**:

- `new Promise` 只接住 `executor` 同步抛出的错误。
- `setTimeout` 回调里的 `throw` 发生在之后另一次调用，Promise 仍是 `pending`，`catch` 不执行。
- 要在回调里 `reject(err)`，或 `try/catch` 后再 `reject`。

**Details**: [../knowledge/javascript/promise-async-throw.md](../knowledge/javascript/promise-async-throw.md)
