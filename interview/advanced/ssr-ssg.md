# SSR / SSG 与 Hydration

## 一、为什么需要 SSR

- SEO 更友好（爬虫可直接拿到完整 HTML）。
- 首屏更快（弱网下用户更早看到内容）。

## 二、SSR 与 SSG 区别

- **SSR**：请求时服务端动态渲染，适合强动态页面。
- **SSG**：构建时生成静态页面，适合内容稳定页面（文档、博客、营销页）。

## 三、Hydration（注水）

服务端先输出 HTML，客户端再把事件与状态“接管”到现有 DOM 上。

### 面试常见点

- 为什么会 Hydration mismatch：服务端与客户端渲染结果不一致。
- 常见原因：时间戳、随机数、浏览器专属 API 在服务端执行。

## 四、框架实践

- Next.js（React 生态）和 Nuxt（Vue 生态）都支持 SSR/SSG 混合模式。
- 实际项目常按页面粒度选择渲染策略，而不是全站统一。
