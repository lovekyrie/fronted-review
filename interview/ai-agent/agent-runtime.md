# Agent Runtime

## 核心结论

Agent Runtime 解决的是“Agent 如何以产品形态稳定运行”。它不只包括模型请求，还包括任务状态、流式输出、工具调用事件、取消重试、人工确认、语音输入输出、定时触发、权限审计和前端渲染协议。

前端工程师在 Agent 项目里的核心价值，往往体现在 Runtime UI：用户要看得懂 Agent 正在做什么，能在关键步骤确认或中断，失败后能恢复，而不是只能等待一段不可解释的文本输出。

## 工程链路

```text
用户创建任务
  -> Runtime 创建 runId / traceId
  -> SSE 推送 task.started
  -> 模型流式输出 assistant.delta
  -> 工具调用推送 tool.started / tool.finished / tool.failed
  -> 高风险动作进入 approval.required
  -> 用户确认、取消或修改参数
  -> Runtime 继续执行或回滚
  -> 推送 task.finished
  -> 保存 trace、成本、耗时和反馈
```

## 关键概念

### SSE 流式接口

SSE 适合服务端向浏览器单向推送事件。相比一次性返回完整答案，SSE 可以让前端实时展示模型 token、任务阶段、工具调用、错误和完成状态。

常见事件类型：

| 事件 | 含义 |
|------|------|
| `task.started` | 任务创建成功 |
| `assistant.delta` | 模型增量文本 |
| `tool.started` | 工具开始调用 |
| `tool.finished` | 工具返回结果 |
| `approval.required` | 需要用户确认 |
| `task.failed` | 任务失败 |
| `task.finished` | 任务完成 |

### AGUI 类协议

AGUI 类协议关注 Agent 与 UI 的事件约定。它不是只传文本，而是把 Agent 执行过程拆成可渲染事件，例如消息、工具卡片、表单确认、进度、错误和结果引用。

前端协议设计要考虑：

- 事件类型稳定，支持版本演进。
- 每个事件有 `runId`、`messageId` 或 `toolCallId`。
- 支持断线重连和事件回放。
- 支持取消、重试和用户确认。

### 语音 ASR / TTS

语音 Agent 需要把语音识别 ASR、文本推理和语音合成 TTS 串起来。前端要处理录音权限、分片上传、实时转写、中断播放、延迟感知和多轮对话状态。

语音场景比文本更强调低延迟和可打断。用户说话时要能停止 TTS，模型执行工具时要能用简短状态提示降低等待焦虑。

### 定时任务

定时任务让 Agent 从“被动回答”变成“主动执行”。例如每天检查构建状态、汇总监控异常、生成学习复盘。工程上必须处理触发条件、权限、幂等、通知和失败重试。

### 人工确认

只要涉及写操作、支付、删除、发布、对外发送消息，都应该引入人工确认。确认界面不应该只显示“是否继续”，还要展示工具名、关键参数、影响范围和可撤销性。

## 常见坑点

- SSE 只传 token，不传工具状态，用户不知道 Agent 卡在哪里。
- 没有 runId 和 toolCallId，前端无法合并事件或回放任务。
- 取消按钮只停止前端渲染，后端任务还在继续执行。
- 断线后不能恢复，长任务体验不稳定。
- 高风险工具没有确认步骤，误操作成本高。
- 语音播放不能被用户打断，体验接近语音播报而不是对话。
- 定时任务没有幂等设计，重试后重复创建工单或通知。

## 面试回答模板

> 我会把 Agent Runtime 设计成事件驱动的任务系统，而不是简单的流式聊天接口。每次任务有 runId 和 traceId，服务端通过 SSE 推送模型增量、工具调用、人工确认、错误和完成事件。前端根据事件渲染消息、工具卡片、进度和确认表单，并提供取消、重试和断线恢复。对于语音和定时任务，我会额外关注低延迟、可打断、幂等和权限审计，避免 Agent 在用户不可见的情况下执行高风险动作。

## 后续实战方向

- 为知识库问答设计一套 SSE 事件协议，区分文本、引用、工具调用和错误。
- 做一个工具调用卡片组件，展示工具状态、参数摘要、耗时和结果。
- 实现任务取消语义，确保前端取消会传递到后端执行层。
- 设计一个每日学习复盘定时 Agent，只生成草稿，不自动发送。
