## 速记卡 / 知识点

### 部署交付 15 题答题本

1. **CI 和 CD 区别**：CI 是质量门禁，CD 是把通过校验的产物稳定交付到目标环境。
2. **自动部署为什么不等于 CI/CD**：没有 lint、测试、构建验证、部署后验证和回滚，只是自动执行发布动作。
3. **前端交付单元有哪些**：静态资源目录、Docker 镜像、平台托管产物；镜像更利于环境一致和版本回滚。
4. **GitHub Actions 核心概念**：`on` 控制触发，`jobs` 组织任务，`steps` 顺序执行，`secrets/artifacts/environment` 支撑发布治理。
5. **CI 怎么提速**：缓存依赖、并行 job、减少无效触发、分层测试、定位构建耗时，不跳过关键门禁。
6. **前端为什么用多阶段 Docker 构建**：Node 负责 build，Nginx 负责 serve，最终镜像更小、更干净。
7. **Docker 缓存怎么设计**：先复制 package 和 lockfile 安装依赖，再复制源码，配合 `.dockerignore` 控制 context。
8. **Nginx 在前端部署里的职责**：静态资源服务、SPA fallback、缓存头、gzip、反向代理和简单安全头。
9. **SPA 刷新 404 怎么解决**：Nginx `try_files` 回退到 `index.html`，但 API 和真实静态资源不能错误 fallback。
10. **HTML 和静态资源缓存怎么配**：HTML 短缓存或 `no-cache`，hash 静态资源长缓存并保留旧版本。
11. **构建时注入和运行时注入区别**：构建时变量固化进产物，运行时配置支持同一产物部署多环境。
12. **为什么前端变量不能放 secret**：进入浏览器 bundle 或配置文件后用户可见，密钥只能留在服务端或 CI secret。
13. **发布策略怎么选**：低风险可覆盖式，高稳定要求用蓝绿，多实例用滚动，大流量用灰度/金丝雀。
14. **回滚为什么回滚产物**：产物已验证、可追溯、可直接运行；临时重新构建会引入新的不确定性。
15. **上线白屏怎么排查**：按 JS 错误、资源加载、接口网络、缓存、环境配置分类，并先止损后根因。

## 手写 / 流程图

```text
开发提交代码
  -> PR：lint / typecheck / test / build
  -> merge main：触发发布 workflow
  -> 构建：安装依赖、生成 dist、生成 source map
  -> 镜像：Docker multi-stage build，打 commit SHA tag
  -> 推送：registry / artifact
  -> 部署：服务器拉镜像，停旧容器，起新容器
  -> Nginx：静态资源、SPA fallback、gzip、缓存头
  -> 浏览器：拉 index.html，加载 hash JS/CSS
  -> 验证：首页、关键路由、核心接口、错误率
  -> 监控：release、source map、Web Vitals、业务指标
  -> 异常：灰度暂停 / 切回上一镜像 / 刷 CDN / 复盘
```

## 口述题

### 1. 从 push 到上线，你的团队是怎么跑的？

> 回答模板：我会把它拆成 CI、产物、部署、验证和回滚五段。开发提交 PR 后先跑 lint、类型检查、测试和构建校验，保证主干质量。合并到主干后触发发布 workflow，构建前端 dist，生成 source map，并通过 Docker 多阶段构建产出镜像，镜像用 commit SHA 或版本号打 tag 后推到 registry。部署阶段服务器拉取指定镜像，启动 Nginx 容器托管静态资源，并配置 SPA fallback、gzip 和缓存头。部署完成后不是立刻结束，而是检查首页、关键路由、核心接口和错误监控。如果发现白屏、资源 404 或指标异常，就按预案切回上一稳定镜像或静态资源版本。

### 2. 3 道自抽追问

> 回答模板：
>
> 1. **为什么自动部署不等于完整 CI/CD？** 因为完整链路要有质量门禁、可追溯产物、部署后验证、监控和回滚；只要缺少这些，自动化可能只是更快地把错误发布出去。
> 2. **为什么回滚要回滚产物而不是代码？** 因为线上运行的是构建后的产物或镜像。回滚代码再重新构建会受到依赖版本、构建环境、配置参数影响，不能保证得到上一份稳定产物。
> 3. **为什么部署后验证不是可选项？** 因为脚本成功只说明命令执行完了，不代表用户可用。资源缺失、缓存错乱、Nginx fallback、接口域名错误都可能在部署后才暴露。

## 今日复盘

最容易被击穿的 3 个问题：

1. 只会说“GitHub Actions 自动部署”，但说不出 CI 质量门禁和 CD 交付验证的边界。
2. 只会说“Docker + Nginx”，但说不出多阶段构建、镜像 tag、缓存头和回滚的关系。
3. 只会说“出问题就回滚”，但说不出回滚触发条件、版本追踪、旧资源保留和验证动作。

本周新增的 3 个“为什么”：

1. 为什么 `latest` 会削弱精准回滚能力？
2. 为什么 `index.html` 不能像 hash JS 一样长期强缓存？
3. 为什么 source map 要进入发布链路，而不是只留在本地？
