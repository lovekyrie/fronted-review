## 速记卡 / 知识点

### 综合面评分维度

| 维度 | 好的表现 | 差的表现 |
|------|----------|----------|
| **工程广度** | 回答自然带出监控/测试/构建/部署 | 只讲功能实现 |
| **决策能力** | 方案有取舍、有理由、有对比 | 只列方案不做选择 |
| **表达控场** | 节奏好，主动引导，知道何时收 | 被面试官牵着走 |
| **项目深度** | "我"做了什么 + 量化 + 追问不慌 | "我们"做了 + 无数据 |

### 综合面时间分配

```text
技术深挖（30min）：挑简历上的技术点深挖 3-4 题
项目（30min）：核心项目 STAR + 2-3 层追问
架构/场景（15min）：设计一个系统/解决一个开放性问题
HR（15min）：离职原因 / 规划 / 薪资 / 反问
```

### 架构题答题结构

```text
1. 确认需求（30s）："这个系统的核心场景是？用户量级？"
2. 顶层设计（60s）：画出主要模块和数据流
3. 关键决策（60s）：技术选型 + 取舍理由
4. 边界处理（30s）：异常、降级、安全
5. 可扩展性（30s）：未来演进方向
```

### 项目表达 Checklist

```text
□ 永远用"我"不用"我们"
□ 有具体数字（LCP / 转化率 / 事故率）
□ 说出为什么这么选（不只是做了什么）
□ 主动提一个你踩过的坑和解决方案
□ 准备好"如果重来"的反思
```

## 手写 / 流程图

### 架构题示例：设计一个前端埋点系统

```text
需求确认：
  - 用户行为埋点（点击、页面停留）+ 性能埋点（LCP/CLS）+ 错误埋点
  - DAU 100 万级，日均上报量 1000 万条
  - 要支持实时告警 + 离线分析

顶层设计：
  浏览器
    └─ 埋点 SDK（自动 + 手动）
        ├─ 采集层：全局监听 + 声明式指令 + 手动 API
        ├─ 处理层：格式化 + 采样 + 聚合 + 批量缓冲
        └─ 上报层：sendBeacon / fetch keepalive
            ↓
  网关（Kafka 队列）
    ├─ 实时管道 → Flink → 告警（钉钉/邮件）
    └─ 离线管道 → ClickHouse → 可视化面板（Grafana）

关键决策：
  - SDK 用 sendBeacon 而不是 XHR → 页面卸载不丢数据
  - 采样率可配（P0 错误 100%，行为埋点 10%）→ 控制成本
  - 批量缓冲（5s 或 10 条触发上报）→ 减少请求数

边界：
  - 网络断开 → 缓存到 IndexedDB，恢复后补传
  - SDK 自身报错 → try-catch 兜底，不影响业务
```
