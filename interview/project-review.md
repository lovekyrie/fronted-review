# 项目复盘（STAR 模板）

建议准备 2~3 个你最有代表性的项目，用 STAR 结构讲清楚。

## 一、STAR 模板

### S（Situation）背景

- 业务目标是什么？
- 你负责的模块边界是什么？

### T（Task）任务

- 当时的核心问题是什么？
- 有哪些时间/资源约束？

### A（Action）行动

- 你如何定位问题（工具、方法）？
- 你做了哪些关键改造？

### R（Result）结果

- 指标提升了多少？
- 有无可复用方案沉淀到团队？

## 二、示例：首屏性能优化

- **S**：活动页转化率低，首屏白屏时间长。
- **T**：两周内把关键指标拉到可接受区间。
- **A**：
  - 用 Performance + Lighthouse 定位问题：包体积大、首屏资源阻塞。
  - 做路由懒加载、公共依赖拆分、图片 WebP、Gzip/Brotli。
  - 增加 `preload` 关键资源，非关键资源延迟加载。
- **R**：
  - LCP 从 4s 降到 1.2s。
  - 首屏 JS 体积下降 40%+。
  - 活动页转化率提升（可填你真实数据）。

## 三、复盘高频追问

- 你做的方案里，收益最高的是哪一个？
- 如果再做一次，你会改哪里？
- 如何证明优化不是“感觉快”，而是“数据快”？

## 四、项目复盘万能讲述模板（3 分钟）

```text
背景：这个项目的业务目标是 XXX，当时核心问题是 XXX，影响指标是 XXX。
任务：我负责的范围是 XXX，需要在 X 周内达成 XXX。
行动：我先通过 XXX 定位根因，再做了 1) XXX 2) XXX 3) XXX。
结果：核心指标从 A 提升到 B，线上问题率下降 C%，并沉淀了 XXX 规范/工具。
复盘：最有效动作是 XXX；如果再做一次，我会提前做 XXX。
```

## 五、可量化指标清单（建议至少准备 6 个）

- 性能：LCP、FCP、CLS、接口耗时、包体积、首屏时间。
- 稳定性：JS 错误率、白屏率、接口失败率、告警数。
- 业务：转化率、留存、下单率、人均停留时长。
- 效率：发布频率、回滚率、构建时长、CI 通过率。

## 六、面试官追问应对

### Q1：这个结果怎么证明是你做的改动带来的？

- 回答要点：A/B 对比、灰度数据、上线前后同口径监控、排除其他变量影响。

### Q2：有没有做失败的尝试？

- 回答要点：先承认，再说明为什么失败、怎么止损、最终怎么修正。

### Q3：你在这个项目里最核心的价值是什么？

- 回答要点：从“写代码”升级为“问题闭环能力”（定位 -> 方案 -> 推动 -> 验证）。

```text
第 1 层：你做了什么？→ STAR 正文

```

### Day 76：项目 STAR 示例模板

```text
项目 A：电商首页性能优化
────────────────────────────────────────
S: 电商首页 LCP P75 = 4.2s，跳出率高于行业平均，产品要求优化到 2.5s 以下
T: 作为前端负责人，主导首页性能优化，目标 LCP < 2.5s
A:
  1. 用 Lighthouse + CrUX 定位瓶颈：首屏大图未 preload，JS 280KB 阻塞渲染
  2. 图片：WebP + preload + fetchpriority="high" + CDN
  3. JS：按路由 Code Split，首屏 chunk 280KB → 90KB
  4. CSS：Critical CSS 内联，非关键 CSS async
  5. 建立 Lighthouse CI 防止劣化
R: LCP P75 降到 2.1s，跳出率降 15%，后续持续用 web-vitals RUM 监控

追问预案：
  Q: 为什么不用 SSR？→ 当时团队没有 Node 运维能力，ROI 不如静态优化
  Q: 如果重来？→ 会更早引入 Lighthouse CI，避免发版劣化
```

```text
项目 B：后台权限系统重构
────────────────────────────────────────
S: 后台权限硬编码在前端路由里，每次加角色要改代码发版，运营频繁找开发
T: 设计动态权限系统，支持运营自助配置角色和菜单
A:
  1. 设计三层权限：接口级（后端中间件）+ 路由级（动态 addRoute）+ 按钮级（v-auth 指令）
  2. 后端出权限 API，前端根据返回动态生成路由和菜单
  3. 封装 v-auth 指令 + useAuth hook，团队统一使用
  4. 补了权限相关的组件测试
R: 运营可自助配置，前端发版频率降低 40%，权限相关 bug 降低 70%

追问预案：
  Q: 菜单和路由怎么同步？→ 同一份数据源，菜单从路由配置派生
  Q: 前端权限能防攻击吗？→ 不能，只是体验兜底，后端必须校验
```
