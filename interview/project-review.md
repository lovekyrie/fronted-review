# 项目复盘（STAR 模板）

建议准备 2~3 个你最有代表性的项目，用 STAR 结构讲清楚。

## 一、STAR 模板

### S（Situation）背景

- 业务目标是什么？
- 你负责的模块边界是什么？

### T（Task）任务

- 当时的核心问题是什么？
- 有哪些时间/资源约束？

### A（Action）行动

- 你如何定位问题（工具、方法）？
- 你做了哪些关键改造？

### R（Result）结果

- 指标提升了多少？
- 有无可复用方案沉淀到团队？

## 二、示例：首屏性能优化

- **S**：活动页转化率低，首屏白屏时间长。
- **T**：两周内把关键指标拉到可接受区间。
- **A**：
  - 用 Performance + Lighthouse 定位问题：包体积大、首屏资源阻塞。
  - 做路由懒加载、公共依赖拆分、图片 WebP、Gzip/Brotli。
  - 增加 `preload` 关键资源，非关键资源延迟加载。
- **R**：
  - LCP 从 4s 降到 1.2s。
  - 首屏 JS 体积下降 40%+。
  - 活动页转化率提升（可填你真实数据）。

## 三、复盘高频追问

- 你做的方案里，收益最高的是哪一个？
- 如果再做一次，你会改哪里？
- 如何证明优化不是“感觉快”，而是“数据快”？

## 四、项目复盘万能讲述模板（3 分钟）

```text
背景：这个项目的业务目标是 XXX，当时核心问题是 XXX，影响指标是 XXX。
任务：我负责的范围是 XXX，需要在 X 周内达成 XXX。
行动：我先通过 XXX 定位根因，再做了 1) XXX 2) XXX 3) XXX。
结果：核心指标从 A 提升到 B，线上问题率下降 C%，并沉淀了 XXX 规范/工具。
复盘：最有效动作是 XXX；如果再做一次，我会提前做 XXX。
```

## 五、可量化指标清单（建议至少准备 6 个）

- 性能：LCP、FCP、CLS、接口耗时、包体积、首屏时间。
- 稳定性：JS 错误率、白屏率、接口失败率、告警数。
- 业务：转化率、留存、下单率、人均停留时长。
- 效率：发布频率、回滚率、构建时长、CI 通过率。

## 六、面试官追问应对

### Q1：这个结果怎么证明是你做的改动带来的？

- 回答要点：A/B 对比、灰度数据、上线前后同口径监控、排除其他变量影响。

### Q2：有没有做失败的尝试？

- 回答要点：先承认，再说明为什么失败、怎么止损、最终怎么修正。

### Q3：你在这个项目里最核心的价值是什么？

- 回答要点：从“写代码”升级为“问题闭环能力”（定位 -> 方案 -> 推动 -> 验证）。
