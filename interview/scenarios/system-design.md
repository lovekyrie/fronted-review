# 系统设计题：组件库、监控 SDK、全局弹窗

## 一、如何设计一个通用组件库

### 目标

- 高复用、可主题化、可按需加载、类型完善。

### 设计要点

- 目录分层：基础组件、业务组件、工具层。
- API 规范：命名统一、受控/非受控模式一致。
- 样式方案：CSS Variables + Design Token。
- 工程能力：文档站、单测、E2E、变更日志、版本策略。

### 面试加分点

- Tree-shaking 友好导出（ESM）。
- 组件无障碍（a11y）与国际化支持。

## 二、如何设计一个前端监控 SDK

### 数据采集

- 错误：`window.onerror`、`unhandledrejection`、框架错误边界。
- 性能：FCP/LCP/CLS/INP、资源耗时、接口耗时。
- 行为：PV、路由切换、关键点击链路。

### 上报策略

- 采样（按环境、用户、页面分层）。
- 批量 + 节流上报（优先 `sendBeacon`）。
- 离线补偿（失败重试 + 本地队列）。

### 治理能力

- 隐私脱敏、黑名单、动态配置下发。
- SourceMap 还原堆栈与版本关联。

## 三、如何设计一个全局弹窗组件

### 关键能力

- 命令式调用：`open`, `close`, `confirm`, `destroy`。
- 队列机制：多弹窗串行/并行策略。
- 生命周期：打开、确认、取消、关闭回调。
- 可访问性：焦点锁定、Esc 关闭、背景滚动锁定。

### 常见坑

- 弹窗销毁不彻底导致内存泄漏。
- 多实例 z-index 冲突。
- 异步确认按钮重复提交（要有 loading 锁）。

## 四、通用答题模板

1. 先定义目标与边界。
2. 再拆核心模块与主链路。
3. 补充稳定性与可观测性设计。
4. 最后讲演进路径与落地收益。
